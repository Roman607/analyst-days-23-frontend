# ТЗ фронтенда — Analyst Days 23

Очный участник Analyst Days 23 должен за две минуты пройти на телефоне от лендинга до скачанного маршрута на 20–21 ноября 2026 года. Между параллельными докладами можно выбрать зал сразу или сохранить оба варианта и решить позже.

**Результат разработки** — приложение на Next.js, Tailwind CSS и shadcn/ui в репозитории `analyst-days-23-frontend`. Два экрана получают программу и персональную подборку от FastAPI по HTTP на том же домене. Единственный формат выгрузки MVP — PNG. [Сценарий MVP](<Сценарий MVP — Очная траектория Analyst Days 23.md>) · [Кликабельный макет](Макеты/ad23-track.html) · [ТЗ бэкенда](<ТЗ бэкенда — Analyst Days 23.md>)

## Лендинг и программа

1. На лендинге объяснить, как выбрать доклады по интересам и сохранить маршрут на телефон. Рядом показать пример с временем и залами. Кнопка **«Выбрать траекторию»** открывает программу. В мобильной версии кнопка расположена перед примером.
2. При открытии программы вызвать `GET /api/program`. Пока идёт запрос, показать загрузку. Если программа ещё не получена, при ошибке показать сообщение и кнопку повторной загрузки.
3. Из одного ответа построить полную сетку обоих дней. Даты — отдельными секциями, московское время — по строкам, залы A–D — по столбцам. В карточке показать название, интервал и подпись выступающих, если она есть. Использовать фактические границы блицев и отдельных частей мастер-класса. События с `room_id: null` занимают общую полосу. На телефоне при горизонтальной прокрутке залов время остаётся видимым.
4. Над сеткой вывести темы из `topics`. При первом открытии без сохранённого выбора все темы сняты, карточки нейтральны. Участник уже может выбрать выступление кликом или скачать пустой маршрут. Перерывы, служебные события и хакатон видны в расписании как ориентиры. [Макеты экранов и мобильной сетки](<Макеты/Макеты экранов — Персональный трек Analyst Days 23.md>)

## От действия до ответа API

Для каждого пересчёта отправить `POST /api/trajectory/preview`. Тело содержит `revision` открытой программы, массив уникальных `topic_ids` и полный массив `actions` в порядке кликов после последнего изменения тем или сброса. Все идентификаторы берутся из программы. [Схема и примеры JSON](API/openapi.yaml)

- **Выбор или снятие темы.** Отправить новый набор тем и пустой `actions`. Обновить подборку обоих дней. Снятие последней темы возвращает нейтральную сетку.
- **Клик по выступлению.** Добавить действие `{"op":"choose","entry_id":"…"}`. Приглушённая карточка также доступна для выбора. В занятый интервал остаётся выбранное выступление. Повторный клик сохраняет его в маршруте.
- **Мастер-класс.** Клик по началу выбирает эту часть. Клик по продолжению выбирает также обязательные предыдущие части. У включённого продолжения показать **«Пропустить продолжение»**. Эта кнопка добавляет `skip_continuation` с ID части. Более ранние части остаются в маршруте.
- **«Обновить по фильтру».** Доступность кнопки задаёт `is_custom` последнего подтверждённого ответа. При нажатии отправить текущие темы с пустым `actions`, чтобы вернуть автоматическую подборку.

В ответе `200` связать `items[].entry_id` с карточками программы той же `revision`. Для `selected` показать **«В маршруте»**, для `alternative` — **«Выберите доклад»**. Поле `conflicts_with` перечисляет прямые пересечения карточки. Остальные карточки сохраняют место в сетке. При действующем выборе визуально приглушить выступления вне маршрута. Источник статусов для экрана и изображения — ответ сервера. [Правила расчёта](<API/Контракт API — Очная траектория Analyst Days 23.md>)

## Скачивание, ожидание и ошибки

**«Скачать картинку»** после загрузки программы создаёт в браузере один PNG на оба дня. Для каждой даты вывести строки в порядке `items` с началом и окончанием, названием и залом. У каждой карточки `alternative` поставить текстовую пометку «Вариант». Пустой PNG содержит обе даты и подпись «Доклады пока не выбраны». Размер изображения и переносы должны позволять прочитать длинные названия и последнюю строку на телефоне. Скачивание работает без дополнительного запроса к API.

- Пока идёт пересчёт, оставить доступным последний показанный маршрут, в том числе для скачивания. Только актуальный успешный ответ обновляет выделение, темы, кнопку, кэш и содержимое PNG. При быстрых кликах применять результат для последнего намерения участника. Запоздалый ответ или ошибка более раннего запроса не меняет экран.
- При обрыве соединения или `503 program_unavailable` сохранить подтверждённый выбор. Кнопка «Повторить» отправляет полный вход неудавшегося расчёта. При `422` показать русское пояснение по коду `invalid_request`, `unknown_topic`, `unknown_entry`, `not_selectable` или `not_continuation`. Весь неудавшийся расчёт отклоняется.
- При `409 stale_program` предложить загрузить обновлённую программу. До согласия участника и успешной загрузки доступны прежняя сетка и соответствующий ей PNG. Получив другую версию, сбросить несовместимый выбор и показать нейтральную сетку.

## Возврат во вкладку

Хранить в `sessionStorage` версию программы, темы, упорядоченные действия и время последнего изменения выбора. При обновлении страницы сначала получить программу. Если версия совпадает и прошло строго меньше 20 минут, повторить preview и восстановить карточки и кнопку по ответу. Начиная с 20-й минуты при обновлении открывать нейтральную сетку. Чтение кэша, повтор запроса и скачивание срок не продлевают. В уже открытой странице выбор остаётся доступен.

При недоступном хранилище вести выбор в памяти страницы, после её обновления начинать заново. Темы и клики исключить из журналов. [Нефункциональные требования](<Нефункциональные требования — Analyst Days 23.md>)

## Приёмка фронтенда

1. **Выбор зала на телефоне.** Запустить секундомер на лендинге. Открыть программу, включить «ИИ». На 21 ноября в 16:30–17:10 МСК у Дмитрия Неверова (зал A) и Веры Бонаревой (зал B) видна подпись «Выберите доклад». До клика в PNG оба варианта. Выбрать Бонареву и скачать маршрут. В PNG на 16:30 остаётся зал B с её докладом, выбор первого дня сохранён. Повторный клик даёт тот же результат. Целевой замер — от лендинга до скачивания после выбора зала за две минуты.
2. **Сброс и замена.** После выбора Бонаревой нажать «Обновить по фильтру» — вернутся оба варианта. Выбрать только «Архитектура», заменить Буракова в D на Неверова в A и сменить тему на «ИИ». Ручная замена сброшена, оба варианта видны, кнопка обновления неактивна.
3. **Особые интервалы.** Выбрать два смежных блица, затем занятие, пересекающее оба. В PNG на их время остаётся это занятие. Выбрать продолжение мастер-класса, затем пропустить его. Начало остаётся, в освободившийся интервал можно выбрать другое выступление.
4. **Пустой маршрут и кэш.** Проверить PNG без тем и после первого ручного выбора. Перезагрузить вкладку через 19 и через 20 минут от одного изменения. В первом случае восстанавливаются темы и выделение, во втором сетка нейтральна. Повторить выбор и скачивание при недоступном хранилище.
5. **Согласованность.** Доставить два ответа preview в обратном порядке, затем вызвать ошибку следующего расчёта. Скачать последний показанный маршрут, повторить запрос и сверить новый PNG с экраном. Отдельно получить `stale_program` и проверить состояние до и после загрузки новой версии.

## Поставка

В репозитории подготовить Dockerfile и README с командами запуска, проверки типов, сборки и ссылкой на бэкенд. Сохранить использованные промпты без секретов. В GitHub Actions при pull request и изменении `main` проверить типы, собрать Next.js и Docker-образ. После успешной сборки `main` опубликовать образ в GHCR с тегом по SHA коммита. Передать версию в общий выпуск. Целевой адрес на Timeweb — `https://ad23-track.89.23.100.193.nip.io:8445/`. Приёмка проходит по HTTPS без входа.
